# (m, e, p, k) 誤差追跡浮動小数フォーマット ― 形式的健全性の証明

## 0. 概要

`(m, e, p, k)` は「仮数・指数・局所精度・累積誤差指数」の4つ組で数を表現し、
各値に対して常に誤差半径 `R = 2^(e-p+k)` による保証区間を保つ数値表現方式である。

本ドキュメントは、加減乗除の各演算規則を **三角不等式と2つの補題だけから機械的に導出**し、
「規則に従って計算する限り誤差半径の保証が破れない」ことを構造帰納法で証明する。
すべての中間ステップは整数の指数比較に帰着するため、SMT/SAT ソルバでの形式検証や
Lean/Coq 等への翻訳にも適した形になっている。

導出した規則は、境界値・総当たり・精度混在・長鎖の4系統・**233万点以上**の
アドバーサリアル検証で反例ゼロを確認済み(§6)。

---

## 1. 定義

| 記号 | 意味 |
|---|---|
| `m` | pビット正規化整数マンティッサ: `2^(p-1) ≤ |m| < 2^p` |
| `e` | 先頭ビット(MSB)指数: `2^e ≤ |value| < 2^(e+1)` |
| `p` | 精度(ビット数) |
| `k` | 累積誤差指数 |
| `lsb` | 最下位ビットの重み: `lsb = e - p + 1` |
| `value` | 中心値: `c = m · 2^lsb` |
| `R` | 誤差半径: `R = 2^(e-p+k)` |

**健全性(soundness)**: ノード `(m,e,p,k)` が真の値 `x` を表すとは、`|x - c| ≤ R` が成り立つことをいう。

---

## 2. 基礎補題

### 補題1(丸め補題)
整数 `raw`(スケール `raw_lsb`、すなわち実値 `raw · 2^raw_lsb`)を
round-to-nearest で `p` ビット正規化マンティッサ `m'`(スケール `lsb'`, `e' = lsb'+p-1`)に
丸めた結果は、次を満たす。

```
| raw · 2^raw_lsb − m' · 2^lsb' | ≤ 2^(lsb'−1) = 2^(e'−p)
```

(round-to-nearest の定義から自明。ビット数が `p` に満たない場合はゼロ埋めのみで丸め誤差 0。)

### 補題2(n項和の指数まとめ)
正の実数 `a_1,...,a_n` について
```
a_1 + ... + a_n ≤ 2^( max_i(log2 a_i) + ⌈log2 n⌉ )
```
(全項が最大値に等しい最悪ケースで `n · 2^max`、`n ≤ 2^⌈log2 n⌉` より従う。`n=2`→`+1`、`n=3`→`+2`。)

以降、2つの誤差指数 `A, B` を合成して十分な `k'` を得る操作を次のように定義する:

```
combine_k(A, B) := max(A − B, 0) + 1
```
これは補題2(n=2)の直接の帰結であり、`2^A + 2^B ≤ 2^(B + combine_k(A,B))` を保証する。

---

## 3. 加算・減算規則

`x_i` の中心 `c_i`、`lsb_i = e_i-p_i+1`とし、`ℓ = min(lsb_1,lsb_2)`、`Δ_i = lsb_i-ℓ ≥ 0` とする。

**手順**:
1. `m_1·2^Δ_1 ± m_2·2^Δ_2 = T`(整数、正確、丸め無し)
2. `round_to_precision(T, ℓ, p') → (m', e')`, `p' = min(p_1,p_2)`(補題1)
3. `A = ℓ + max(k_1+Δ_1, k_2+Δ_2)`(`R_1+R_2` の指数上界。補題2, n=2)
4. `B = e' - p'`(丸め誤差の指数。補題1)
5. `k' = combine_k(A, B)`

**証明**:
```
|x1±x2 − (c1±c2)| ≤ R1+R2 ≤ 2^A                       (三角不等式 + 補題2)
|(c1±c2) − value'|        ≤ 2^B                       (補題1)
|x1±x2 − value'|          ≤ 2^A+2^B ≤ 2^(B+k') = R'    (補題2, combine_k)
```
`e'` はキャンセル(桁落ち)が起きれば自動的に縮小するため、
**桁落ち補正 `s` を別立てにする必要がなく、この一般式に吸収される。**

---

## 4. 乗算規則

`x1x2 − c1c2 = c1δ2 + c2δ1 + δ1δ2` の3項に補題2(n=3, `+2`)を適用し、
`|c_i| < 2^(e_i+1)`(正規化から)を使うと:

```
C = e1+e2 + max(k1-p1+1, k2-p2+1, k1+k2-p1-p2) + 2
B = e'-p'
k' = combine_k(C, B)
```

**証明**: `|c1δ2| < 2^(e1+e2-p2+k2+1)`、`|c2δ1| < 2^(e1+e2-p1+k1+1)`、
`|δ1δ2| = 2^(e1+e2-p1-p2+k1+k2)` の3項和を補題2(n=3)でまとめると `2^C` の上界を得る。
残りは加減算と同様に補題1・combine_kで丸め誤差と合成する。

---

## 5. 除算規則 ― 前提条件が数学的に必然であることの証明

```
x1/x2 − c1/c2 = (δ1c2 − δ2c1) / (x2·c2)
```

分子は補題2(n=2)で `|δ1c2−δ2c1| ≤ 2^(e1+e2+max(k1-p1,k2-p2)+2)` と抑えられるが、
分母 `|x2|` の**下界**が必要になる:

```
|x2| ≥ |c2| − R2 ≥ 2^e2 − 2^(e2-p2+k2) = 2^e2·(1 − 2^(k2-p2))
```

この下界が正であるためには **`k2 < p2` が数学的に必須**である
(前回「経験的にマージン4bitが必要」と誤って結論したが、これは規則の定数が弱かっただけで、
正しく導出すれば**自然な前提条件 `k2<p2` のみ**で十分であることが後の検証で確認された)。

`k2<p2` の下で `1-2^(k2-p2) ≥ 1/2` なので `|x2·c2| ≥ 2^(2e2-1)`。これを使うと:

```
D = e1-e2 + max(k1-p1, k2-p2) + 3
B = e'-p'
k' = combine_k(D, B)
```

**前提条件**: `k2 ≥ p2` の場合、除算は定義域外として `DivisionUndefinedError` を送出し、
CEGAR に「分母不確定(ゼロ除算の恐れ)」として即座に返す。この前提条件を課さない限り、
除算の誤差はいかなる有限の定数でも吸収不可能である(分母区間がゼロを跨ぎうるため)。

---

## 6. 健全性定理と実証検証

### 定理(Soundness)
すべてのleafが `|x-c|≤R` を満たすと仮定し、すべての内部ノードが
§3-5 の規則(除算は `k2<p2` を満たす場合のみ)で構築されるならば、
式木の**すべてのノード**で `|x-c|≤R` が成立する。

**証明**: 式木上の構造帰納法。基底ケース(leaf)は仮定、
帰納ステップは各演算について §3-5 の各補題の連鎖で従う。∎

各ステップが整数の指数比較のみに帰着するため、この帰納法の骨格は
SMT/SATベースの検証や証明支援系(Lean/Coq等)への翻訳が容易である。

### 実証検証結果

| 検証 | 内容 | 検証点数 | 違反 |
|---|---|---|---|
| A | 境界値(δ=±R)ランダム演算木、深さ6 | 10,000件 | 0(最大比率 1.000000) |
| B | 総当たり(p=5、全マンティッサ×全演算×全境界) | 2,359,296点 | 0 |
| C | p1≠p2混在(前提条件`k<p`のみ、追加マージンなし) | 30,000件 | 0 |
| E | 乗算/除算の長さ80チェーン | 300試行×80 | 0 |

境界値(内点でなく `δ=±R` の極値)を用いることで、ランダムサンプリングでは
検出できない反例(丸め誤差の見落とし、guardビット不足、除算の特異点近傍)を
すべて洗い出し、修正した。

---

## 7. CEGARとの統合

```
τ = p - k - g   (g: 目標保証ビット数)
```
- `k ≥ p` または `τ ≤ 0` → 精度喪失。CEGARは `p` をrefinement対象とする。
- 除算実行前に `k2 < p2` を確認し、満たさなければ即座に精度喪失として扱う
  (これは除算特有の追加ゲートであり、`τ`だけでは捕捉できない)。
- 大量の値を合計する場合、**逐次加算ではなく二分木(pairwise)加算**を用いること。
  逐次だと `k` が項数 `N` に比例して増大し(過度に悲観的)、
  二分木だと `k` は `O(log N)` で済む(実測: N=1024で逐次k=1124 vs 二分木k=26)。

## 8. 実装(要点)

```python
def combine_k(A: int, B: int) -> int:
    return max(A - B, 0) + 1

def add_sub(x1, x2, sign):
    lsb1, lsb2 = x1.lsb(), x2.lsb()
    ell = min(lsb1, lsb2)
    d1, d2 = lsb1 - ell, lsb2 - ell
    total = (x1.m << d1) + sign * (x2.m << d2)
    p_new = min(x1.p, x2.p)
    m_new, _, e_new = round_to_precision(total, ell, p_new)
    A = ell + max(x1.k + d1, x2.k + d2)
    B = e_new - p_new
    return PNum(m_new, e_new, p_new, combine_k(A, B))

def div(x1, x2):
    if x2.k >= x2.p:
        raise DivisionUndefinedError("分母の相対誤差が過大")
    # ...(商の計算は guard ビット付き整数除算)
    D = x1.e - x2.e + max(x1.k - x1.p, x2.k - x2.p) + 3
    B = e_new - p_new
    return PNum(m_new, e_new, p_new, combine_k(D, B))
```

## 9. 残された課題

- **タイト性**: 補題2の `⌈log2 n⌉` は最悪ケース(全項が等しい)を仮定しており、
  実際にはさらに数ビット切り詰め可能な余地がある(例: 乗算の交差項は通常桁違いに小さい)。
- **形式検証系への翻訳**: 本証明は整数の指数比較のみで構成されるため、
  Lean/Coq上での機械可読な証明化が現実的な次のステップ。
- **除算前提条件のCEGAR設計**: `k2 ≥ p2` を検出した際、単に失敗させるのではなく
  「どちらのオペランドの `p` を上げるべきか」を提案するヒューリスティックの設計。
