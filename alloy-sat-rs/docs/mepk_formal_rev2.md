# (m, e, p, k) 誤差追跡浮動小数フォーマット ― 形式的健全性の証明

## 0. 概要

`(m, e, p, k)` は「仮数・指数・局所精度・累積誤差指数」の4つ組で数を表現し、
各値に対して常に誤差半径 `R = 2^(e-p+k)` による保証区間を保つ数値表現方式である。

本ドキュメントは、加減乗除の各演算規則を **三角不等式と2つの補題だけから機械的に導出**し、
「規則に従って計算する限り誤差半径の保証が破れない」ことを構造帰納法で証明する。
すべての中間ステップは整数の指数比較に帰着するため、SMT/SAT ソルバでの形式検証や
Lean/Coq 等への翻訳にも適した形になっている。

導出した規則は、境界値・総当たり・精度混在・長鎖の4系統・**233万点以上**の
アドバーサリアル検証で反例ゼロを確認済み(§6)。さらに、演算木(式木)を
直接評価しCEGARで自動精緻化する実装まで拡張し、実装中に見つかった
追加の反例2件も修正済み(§9)。

---

## 1. 定義

| 記号 | 意味 |
|---|---|
| `m` | pビット正規化整数マンティッサ: `2^(p-1) ≤ |m| < 2^p` |
| `e` | 先頭ビット(MSB)指数: `2^e ≤ |value| < 2^(e+1)` |
| `p` | 精度(ビット数) |
| `k` | 累積誤差指数 |
| `lsb` | 最下位ビットの重み: `lsb = e - p + 1` |
| `value` | 中心値: `c = m · 2^lsb` |
| `R` | 誤差半径: `R = 2^(e-p+k)` |

**健全性(soundness)**: ノード `(m,e,p,k)` が真の値 `x` を表すとは、`|x - c| ≤ R` が成り立つことをいう。

---

## 2. 基礎補題

### 補題1(丸め補題)
整数 `raw`(スケール `raw_lsb`、すなわち実値 `raw · 2^raw_lsb`)を
round-to-nearest で `p` ビット正規化マンティッサ `m'`(スケール `lsb'`, `e' = lsb'+p-1`)に
丸めた結果は、次を満たす。

```
| raw · 2^raw_lsb − m' · 2^lsb' | ≤ 2^(lsb'−1) = 2^(e'−p)
```

(round-to-nearest の定義から自明。ビット数が `p` に満たない場合はゼロ埋めのみで丸め誤差 0。)

### 補題2(n項和の指数まとめ)
正の実数 `a_1,...,a_n` について
```
a_1 + ... + a_n ≤ 2^( max_i(log2 a_i) + ⌈log2 n⌉ )
```
(全項が最大値に等しい最悪ケースで `n · 2^max`、`n ≤ 2^⌈log2 n⌉` より従う。`n=2`→`+1`、`n=3`→`+2`。)

以降、2つの誤差指数 `A, B` を合成して十分な `k'` を得る操作を次のように定義する:

```
combine_k(A, B) := max(A − B, 0) + 1
```
これは補題2(n=2)の直接の帰結であり、`2^A + 2^B ≤ 2^(B + combine_k(A,B))` を保証する。

---

## 3. 加算・減算規則

`x_i` の中心 `c_i`、`lsb_i = e_i-p_i+1`とし、`ℓ = min(lsb_1,lsb_2)`、`Δ_i = lsb_i-ℓ ≥ 0` とする。

**手順**:
1. `m_1·2^Δ_1 ± m_2·2^Δ_2 = T`(整数、正確、丸め無し)
2. `round_to_precision(T, ℓ, p') → (m', e')`, `p' = min(p_1,p_2)`(補題1)
3. `A = ℓ + max(k_1+Δ_1, k_2+Δ_2)`(`R_1+R_2` の指数上界。補題2, n=2)
4. `B = e' - p'`(丸め誤差の指数。補題1)
5. `k' = combine_k(A, B)`

**証明**:
```
|x1±x2 − (c1±c2)| ≤ R1+R2 ≤ 2^A                       (三角不等式 + 補題2)
|(c1±c2) − value'|        ≤ 2^B                       (補題1)
|x1±x2 − value'|          ≤ 2^A+2^B ≤ 2^(B+k') = R'    (補題2, combine_k)
```
`e'` はキャンセル(桁落ち)が起きれば自動的に縮小するため、
**桁落ち補正 `s` を別立てにする必要がなく、この一般式に吸収される。**

---

## 4. 乗算規則

`x1x2 − c1c2 = c1δ2 + c2δ1 + δ1δ2` の3項に補題2(n=3, `+2`)を適用し、
`|c_i| < 2^(e_i+1)`(正規化から)を使うと:

```
C = e1+e2 + max(k1-p1+1, k2-p2+1, k1+k2-p1-p2) + 2
B = e'-p'
k' = combine_k(C, B)
```

**証明**: `|c1δ2| < 2^(e1+e2-p2+k2+1)`、`|c2δ1| < 2^(e1+e2-p1+k1+1)`、
`|δ1δ2| = 2^(e1+e2-p1-p2+k1+k2)` の3項和を補題2(n=3)でまとめると `2^C` の上界を得る。
残りは加減算と同様に補題1・combine_kで丸め誤差と合成する。

## 5. 除算規則 ― 前提条件が数学的に必然であることの証明

```
x1/x2 − c1/c2 = (δ1c2 − δ2c1) / (x2·c2)
```

分子は補題2(n=2)で `|δ1c2−δ2c1| ≤ 2^(e1+e2+max(k1-p1,k2-p2)+2)` と抑えられるが、
分母 `|x2|` の**下界**が必要になる:

```
|x2| ≥ |c2| − R2 ≥ 2^e2 − 2^(e2-p2+k2) = 2^e2·(1 − 2^(k2-p2))
```

この下界が正であるためには **`k2 < p2` が数学的に必須**である
(前回「経験的にマージン4bitが必要」と誤って結論したが、これは規則の定数が弱かっただけで、
正しく導出すれば**自然な前提条件 `k2<p2` のみ**で十分であることが後の検証で確認された)。

`k2<p2` の下で `1-2^(k2-p2) ≥ 1/2` なので `|x2·c2| ≥ 2^(2e2-1)`。これを使うと:

```
D = e1-e2 + max(k1-p1, k2-p2) + 3
B = e'-p'
k' = combine_k(D, B)
```

**前提条件**: `k2 ≥ p2` の場合、除算は定義域外として `DivisionUndefinedError` を送出し、
CEGAR に「分母不確定(ゼロ除算の恐れ)」として即座に返す。この前提条件を課さない限り、
除算の誤差はいかなる有限の定数でも吸収不可能である(分母区間がゼロを跨ぎうるため)。

### P0-1 補足: 二段丸めと `Q` 項 (実装で発見された反例の修正)

商の中心は整数除算の都合で **二段丸め** (`scaled_div_nearest` による事前丸め
`E1 ≤ 2^(q_lsb−1)`、`Q = q_lsb − 1`、次に `round_to_precision` の `E2 ≤ 2^B`)
を経る。§5 の導出は中心計算を単発の補題1丸めとして扱っており、`E1` の吸収が
抜けていた。zero-fill は `lsb'` を `q_lsb` より下げうるため、`E1` は `2^B`
も `2^D` も大幅に上回りうる。具体的な反例 (guard 0):

- `(23,-1,5,0)/(44,1,6,0)`: 真の商 `0.2614...` に対し旧規則は中心 `0.5`,
  `R' = 0.125` (区間外)。
- `(18,3,5,0)/(-29,1,5,1)`: 半径が lane の `B` を読むため、`B` 側への
  繰り込みでは直らず、`D` 側への繰り込みが必須。

修正: 入力誤差予算に事前丸め指数を畳み込む。`D' = max(D, Q) + 1`、
`k' = combine_k(D', B)` とすると、`2^D + 2^Q ≤ 2^D'` (補題2) から
`+ 2^B ≤ 2^(B+k') = R'` が従う (ゼロ商経路では `E2 = 0` のため同様)。
この修正は事前丸めが支配的な場合 (`Q ≥ max(D, B)`) にのみ出力を変え、
それ以外では `R'` はビット一致する (タイト性最適)。

帰結: `guard` は健全性ではなくタイト性のノブである (大きいほど `Q` が
小さくなり、ゼロ商しきい値も下がる)。健全性はすべての `guard ≥ 0` で
成立する。前提条件は lowering の Phase-2 と一致する
(分母正規化-nonzero、分子上限、wellformed `k ≥ 0`、`k2 < p2`、`m2 ≠ 0`)。
`alloy-kodkod-rs/src/mepk.rs` の `div_two_stage_sound_fuzz`
(guard 0–6、境界値 `δ = ±R`、3万点近傍の exact 検証) が定理を裏付ける。

### P0-2 補足: 10進リテラル変換の二段丸め (欠落なしの確認)

非dyadic リテラル (`0.1` 等) の変換も二段丸め
(スケール事前丸め + `round_to_precision`) を経るが、こちらは健全であり
`k = 1` で足りる。理由: プリスケール `s = max_p − e_est + 2`
(`e_est = floor(log2 value)`) により、つねに `q ≈ V·2^s ≥ 2^(max_p+2)`、
すなわち `bitlen(q) ≥ max_p + 3` となるため、最終丸めは必ず 3 ビット以上
落とす (zero-fill 経路なし)。よって事前丸め誤差 `E1 ≤ 2^(q_lsb−1)` は
`2^B/8` 以下に抑えられ、`E1 + E2 ≤ 1.125·2^B < 2·2^B = R` (`k = 1`) が
成立する。除算 P0-1 との差はここにある (除算は zero-fill で `lsb'` が
`q_lsb` を下回りうるため `Q` 項の繰り込みが必須だった)。
`floor_log2_div` の正確性は本 bound の前提であり (`e_est` の過大評価は
drop を削る)、単体テスト `floor_log2_div_sane` と
`decimal_randomized_sound_fuzz` (8000点近傍の exact 検証 + `err/R < 0.8`
のマージンロック) が裏付ける。dyadic over-cap 経路 (`k = 0` の単発丸め)
は補題1そのものであり、exact tie で `err/R = 1` に達しうる (健全)。

**注意(§9.1で詳述)**: `k2<p2` は「分母の相対誤差が100%未満」を保証するために導いたが、
加減算の結果が完全にキャンセルして中心値がちょうど `m=0` になるケース(正規化の枠外の
特殊値)は、`k2<p2` が成立していてもすり抜ける。実装では `x2.m==0` を独立にガードする
必要がある。

## 6. 健全性定理と実証検証

### 定理(Soundness)
すべてのleafが `|x-c|≤R` を満たすと仮定し、すべての内部ノードが
§3-5 の規則(除算は `k2<p2` を満たす場合のみ)で構築されるならば、
式木の**すべてのノード**で `|x-c|≤R` が成立する。

**証明**: 式木上の構造帰納法。基底ケース(leaf)は仮定、
帰納ステップは各演算について §3-5 の各補題の連鎖で従う。∎

各ステップが整数の指数比較のみに帰着するため、この帰納法の骨格は
SMT/SATベースの検証や証明支援系(Lean/Coq等)への翻訳が容易である。

### 実証検証結果

| 検証 | 内容 | 検証点数 | 違反 |
|---|---|---|---|
| A | 境界値(δ=±R)ランダム演算木、深さ6 | 10,000件 | 0(最大比率 1.000000) |
| B | 総当たり(p=5、全マンティッサ×全演算×全境界) | 2,359,296点 | 0 |
| C | p1≠p2混在(前提条件`k<p`のみ、追加マージンなし) | 30,000件 | 0 |
| E | 乗算/除算の長さ80チェーン | 300試行×80 | 0 |

境界値(内点でなく `δ=±R` の極値)を用いることで、ランダムサンプリングでは
検出できない反例(丸め誤差の見落とし、guardビット不足、除算の特異点近傍)を
すべて洗い出し、修正した。

## 7. CEGARとの統合

```
τ = p - k - g   (g: 目標保証ビット数)
```
- `k ≥ p` または `τ ≤ 0` → 精度喪失。CEGARは `p` をrefinement対象とする。
- 除算実行前に `k2 < p2` を確認し、満たさなければ即座に精度喪失として扱う
  (これは除算特有の追加ゲートであり、`τ`だけでは捕捉できない)。
- 大量の値を合計する場合、**逐次加算ではなく二分木(pairwise)加算**を用いること。
  逐次だと `k` が項数 `N` に比例して増大し(過度に悲観的)、
  二分木だと `k` は `O(log N)` で済む(実測: N=1024で逐次k=1124 vs 二分木k=26)。

## 8. 実装(要点)

```python
def combine_k(A: int, B: int) -> int:
    return max(A - B, 0) + 1

def add_sub(x1, x2, sign):
    lsb1, lsb2 = x1.lsb(), x2.lsb()
    ell = min(lsb1, lsb2)
    d1, d2 = lsb1 - ell, lsb2 - ell
    total = (x1.m << d1) + sign * (x2.m << d2)
    p_new = min(x1.p, x2.p)
    m_new, _, e_new = round_to_precision(total, ell, p_new)
    A = ell + max(x1.k + d1, x2.k + d2)
    B = e_new - p_new
    return PNum(m_new, e_new, p_new, combine_k(A, B))

def div(x1, x2):
    if x2.k >= x2.p:
        raise DivisionUndefinedError("分母の相対誤差が過大")
    # ...(商の計算は guard ビット付き整数除算)
    D = x1.e - x2.e + max(x1.k - x1.p, x2.k - x2.p) + 3
    B = e_new - p_new
    return PNum(m_new, e_new, p_new, combine_k(D, B))
```

## 9. 演算木(式木)への対応とCEGARループ

### 9.0 構成

- **Expr AST**: `Leaf`(真の値+初期精度 `p`)と `BinOp`(演算子+左右の子)。
  Python の `+ - * /` 演算子オーバーロードにより `(a*b - c*d) / (e-f)` のように自然に書ける。
- **`evaluate(expr)`**: 式木をボトムアップに評価し、各ノードの `(m,e,p,k)` と
  「真の値」を同時に追跡する(真の値はテスト・デモ用にFractionで厳密に伝播)。
- **`cegar_evaluate(expr, g, delta)`**: `τ=p-k-g≤0` や `k≥p`、除算前提条件違反を
  検出したら、原因箇所を絞り込んで該当の葉の `p` だけを引き上げ再評価する
  refinementループ。

### 9.1 実装中に見つかった追加の反例(2件)

**(a) 除算: 完全キャンセルによる `m=0` のすり抜け**

前提条件 `k2<p2` は「分母の相対誤差が100%未満」を保証するために導いたが、
加減算の結果が完全にキャンセルして中心値がちょうど `m=0` になるケース
(§3の丸め補題の `raw=0` 分岐、正規化 `2^(p-1)≤|m|<2^p` の枠外の特殊値)は、
`k2<p2` が成立していてもすり抜ける。`m=0` のとき相対誤差は定義上無限大であり、
除算は常に定義域外として扱う必要がある。

```python
if x2.m == 0:
    raise DivisionUndefinedError("分母の中心値がちょうどゼロ(完全キャンセル)")
```

**(b) CEGARの絞り込みヒューリスティックの発散**

当初「`k`が大きい方の子を辿って葉を1つだけ引き上げる」方式を採用したところ、
桁落ちが起きる減算(例: `e-f`, `e≈f`)を含む式で**無限ループ**した。

原因は加減算規則の `p'=min(p1,p2)` という構造にある。桁落ちで発生する `k` の増大は
**両オペランドに共通のボトルネック `p'`** に起因するため、`k`の大小だけで片方の葉を
選んで精度を上げても `p'=min(p1,p2)` は変わらず、収束しない。

修正: 木全体をトレースし、**`p-k` マージンが最小のノード**(最も精度を消費した箇所)を
特定し、そのノードの**両オペランド配下の葉すべて**を一括で引き上げる。

```python
worst = min(candidates, key=lambda t: t.node.p - t.node.k)
leaves = collect_leaves(worst.expr)   # 両方の子孫を含む
for l in leaves:
    l.p += delta
```

### 9.2 動作例

桁落ちを含む式 `(355·113 − 22·7) / (e−f)`(`e≈f`)を全leaf `p=8` から評価:

```
iter1: 除算前提条件違反(分母部分木) → e,f を p=14 に引き上げ
iter2: 精度不足(k=11,p=8)  → a,b,c,d,e,f をまとめて引き上げ
iter3: 精度不足(k=11,p=14) → さらに引き上げ
iter4: 成功。k=11, p=20, tau=3   (実際の誤差536 ≤ R=65536)
```

このヒューリスティックは「`p-k`マージンが最小のノードを全体から探す」という
**大域的**な判断であり、§4-5で導出した `A,B,C,D` の各項のうちどれが支配的かという
**局所的**な情報までは使っていない(§10で今後の課題として言及)。

### 9.3 本番計算とオラクル検証の分離
初期実装では `Leaf` の中心値が「真の値(オラクル)を`p`ビットに丸める」という
形で作られており、`evaluate()` が中心値と真の値を同時に返す構造になっていた。
`add_sub`/`mul`/`div` 自体は中心値だけから計算していたが、**その入口である
`Leaf` がオラクル由来だった**ため、演算木全体を通じて本番計算と検証用の
真の値追跡が同じ経路に混ざっていた。

これを明確に分離した:

| 関数 | 役割 | オラクル依存 |
|---|---|---|
| `Leaf.__init__` | 入力値を `p` ビットに丸めて `node` を作る(補題1そのもの) | 生成時の入力のみ(オラクルではなく単なる入力値) |
| `evaluate(expr)` | 中心値 `(m,e,p,k)` だけを計算 | **なし** |
| `evaluate_traced(expr)` | 同上 + トレース記録(CEGAR用) | **なし** |
| `cegar_evaluate(expr)` | 精度不足を検出し再精緻化 | **なし**(`node.k`, `node.p` だけで判断) |
| `true_value(expr)` | 真の値を厳密に伝播 | **検証専用**、本番経路からは呼ばれない |
| `verify(expr, node)` | `node` と真の値を比較し境界を確認 | **検証専用** |

`Leaf` は検証用に元の入力値を `exact_value` として保持するが、`evaluate`/
`evaluate_traced`/`cegar_evaluate` はこれを一切参照しない。`cegar_evaluate` が
refinement時に葉の `p` を引き上げる際も、`exact_value`(=その葉が元々表していた
入力値そのもの)を再度 `p` ビットで丸め直しているだけであり、これは「入力を
より高い精度で再表現する」という通常の計算であって、隠れた正解を参照している
わけではない。

この分離により、`evaluate` 系は実運用にそのまま組み込める(入力値だけを与えれば
真の値を一切必要とせず動作する)一方、`true_value`/`verify` は境界 `R` が実際に
誤差を包含しているかを確認するための独立した検証レイヤーとして明確に切り離された。

### 9.4 実装で判明した追加知見: guard 協調精密化の必要性

Rust 移植 (`alloy-kodkod-rs/src/mepk_tree.rs`) の検証中に判明した:
除算を含む式では、葉の `p` 上げだけでは `τ` が収束しない場合がある。
原因は P0-1 の `Q` 項にある。`q_lsb = lsb_1 − lsb_2 − g` は両 `lsb` が
`p` と連動して動くため `p` に依存せず、したがって事前丸め誤差
`E1 ≤ 2^(q_lsb−1)` も `p` 上げでは縮まない。`Q + 1 > max(D, B)`
(`Q`-blocked) の除算ノードが worst の場合、中心精度は guard が律速であり、
`p` 上げは `τ` を永遠に動かさない (実測: `(355·113−22·7)/(1000−999)`
で `τ = 0` に凍結)。

対策: worst ノードが `Q`-blocked な除算の場合は葉ではなく ambient guard
(`MepkWidths::guard` に対応、開始値 4、上限 64) を引き上げる。
`DivUndefined` (定義域違反) に対しては guard は無力なので葉上げのみを
行う。この二刀流により上記 walkthrough は guard 10 で収束する。
guard 上げは全除算を一律に精密化する (単調改善) ため、大域状態でよい。

### 9.5 `m = 0` 空洞と絶対許容 (`abs`)

`τ` 基準はゼロ中心に盲目である: `m = 0` の相対誤差は定義されないため、
`τ > 0` と天文学的な絶対 `R` が両立する (例: 大スケールでの完全キャンセル
`(x−x)`、`x ~ 2^100` → `0 ± 2^94` で `τ = 3`)。非ゼロ中心では
`τ > 0 ⇒ 相対誤差 ≤ 2^(−τ−g+1)` が成立するので、空洞化は `m = 0`
(生成: 加減算の完全キャンセル・除算のゼロ商、伝播のみ: 乗算) に特有である。

実装 (`cegar_evaluate` の `abs_tol`、`abs <rexp>` オプション) は
`R = 2^r` について `r > abs` のノードがある間は継続精密化する。
減算ゼロは `p` 上げで (`R` が `p` と連動)、除算ゼロは guard 協調で収束し、
到達不能な許容は上限 (`p ≤ 127`・guard ≤ 64・`max_iters`) で正直に停止する。
`abs` 未指定の成功時に `m = 0` かつ `R > 1` の root が残った場合は
vacuous 警告を出す (REPL `:cegar`)。solver lowering 側も同一のゼロ規則を
持つが、比較の健全性には影響しないため文書注記にとどめる。

## 10. 残された課題

- **タイト性**: 補題2の `⌈log2 n⌉` は最悪ケース(全項が等しい)を仮定しており、
  実際にはさらに数ビット切り詰め可能な余地がある(例: 乗算の交差項は通常桁違いに小さい)。
- **形式検証系への翻訳**: 本証明は整数の指数比較のみで構成されるため、
  Lean/Coq上での機械可読な証明化が現実的な次のステップ。
- **除算前提条件のCEGAR設計**: `k2 ≥ p2` を検出した際、単に失敗させるのではなく
  「どちらのオペランドの `p` を上げるべきか」を提案するヒューリスティックの設計。
- **CEGAR絞り込みの精密化**: 現行の「`p-k`マージン最小のノードの両葉を一括で
  引き上げる」方式(§9.1(b))は大域的な代理指標であり収束は確認済みだが、
  `A,B,C,D`(§3-5)の各項のうちどれが支配的かという局所情報を使えば、
  加算/減算では「実際に `p_new` を制限している側」だけ、乗算/除算では
  `k1-p1` と `k2-p2` の大小比較で「支配的な誤差項を持つ側」だけを狙い撃ちでき、
  再精緻化の反復回数をさらに減らせる可能性がある。

### P2-2 補足: solver の `k'` 経路の exact 化と wrap 残存の整理

solver lowering の `k'` 経路 (加減乗除の `A/B/C/D`、combine、`lsb` 比較)
はすべて widening-exact 化済みであり、problem bitwidth での wrap は起きない。
`p` の min (`ereal_min_eq`) と lane 比較 (`div_guard`、`m≠0`、区間比較) は
算術を含まないため元々 exact である。残る `Bin` 算術は `ereal_needs_refine`
の `tau` のみであり、これは述語 (要精密化フラグ) にしか使われない。

なお rule 幅 (`MepkWidths::from_rule`) の下では、`k'` 系の wrap を起こす
lane 値は `e'`/`k'` 自体の lane 表現可能性も同時に破るため、wrap の有無で
solver verdict が変わることはない (どちらも UNSAT になるか、wrap 域外で
一致する)。このため wrap の差分テストは存在せず、exact 化は
広幅 (`MEPK_*_WIDTH` override) への備えと将来の回帰防止のためのものである。
